\section{Discussion}
\label{sec:discussion}

%------------------------------------------------
\subsection{Architectural Findings and Operational Trade-offs}

\textbf{RQ1 (Architecture-Level Effectiveness):}
The tested orchestration bundle has a higher Automated Fact Pass Rate point estimate and fewer recorded specialist input tokens than Single Agent. The Fact Coverage confidence interval spans zero, and latency measures different pipeline stages; neither a completeness nor a speed advantage follows. The 50\% threshold binarizes coverage, so the pass-rate difference does not establish consistently more complete answers. The No Specialist Policy ablation is consistent with a contribution from domain instructions under the evaluated conditions.

\textbf{RQ2 \& RQ3 (Mechanisms, Tool Isolation, and Registry Scaling):}
The ablations associate specialist policies and heterogeneous evidence access with larger pass-rate losses when removed. Without calculators, tuition exact matches fall from 8/9 to 3/9; without route repair, cross-domain pass falls from 80.0\% to 65.0\%. At 11 tools, removing isolation increases input tokens without changing the pass estimate. At 51 tools, Routed Specialist records 88.0\% tool E2E Success, $9.3$\,pp above Global Top-10 (CI $[+2.0, +17.3]$\,pp); its $4.7$\,pp difference over Full-Registry Single Agent remains uncertain (CI $[-1.3, +11.3]$\,pp). These results suggest a benefit from bounded tool exposure under the tested ambiguity.

\textbf{Operational Trade-offs and Deployment Guidance:}
Single-agent timing begins after retrieval, whereas the multi-agent figures include routing; these values cannot rank the architectures by speed. Specialist execution records $1{,}731$\,ms and $677$ output tokens more than generic execution. A single agent may be simpler for a narrow task and small tool pool; scoped specialists may suit institutions with distinct evidence formats and fee calculations. These are deployment considerations, not measured outcomes. Adapting \system{} elsewhere requires mapping curriculum schemas, loading local policies into Neo4j, PostgreSQL, and Qdrant, encoding fee rules in tools, updating intent--owner labels and prompts, and testing against the new institution's regulations.

\subsection{Relation to Prior Work}

ReAct~\cite{yao2023react} and Toolformer~\cite{schick2023toolformer} study tool use; AutoGen~\cite{wu2023autogen} supports agent exchanges. \system{} instead uses one owner and evidence paths selected by data modality, differing from Adaptive-RAG's complexity-based retrieval~\cite{jeong2024adaptiverag}. The Source Recall drop under Uniform Text-RAG is consistent with GraphRAG's rationale for relational evidence~\cite{edge2024graphrag}, although the ablation also changes representation. These frameworks were not directly compared in our experiments.

%------------------------------------------------
\subsection{Threats to Validity}
\label{sec:limitations}
\textbf{Internal and operational:} The $10.65$\,s pipeline latency may limit interactive use. Because Single Agent timing starts after retrieval, the current measurements cannot attribute an inter-architecture speed difference; service and network variation add uncertainty. \textbf{External:} Queries cover one institution, and Scenario~3 uses synthetic tool neighbors. Transfer to other curriculum structures and fee rules remains untested. Redis history and query rewriting were excluded from the fixed-query benchmark, so live multi-turn effects remain unmeasured. \textbf{Construct:} Substring matching can pass an incorrect financial answer: \texttt{HOUT-DIR-FIN-03} reached 50\% coverage despite a 192.183M versus 40M VND discrepancy. Separate tool checks and nine tuition exact-match audits address only parts of this limitation. \textbf{Statistical:} The 100-query paired analysis uses 10,000 bootstrap resamples; the nine-case arithmetic subset remains small.
