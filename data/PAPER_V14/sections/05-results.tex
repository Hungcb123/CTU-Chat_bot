\subsection{Scenario 1 --- Architecture-Level Comparison}
\label{sec:s1_results}

Table~\ref{tab:arch_comparison} compares the three configurations on the 100-query held-out benchmark. Because pre-generation evidence retrieval is held fixed across configurations, Source Recall (78.6\%) and Source AP (70.8\%) are identical across all three architectures. The observed differences in final answer quality and operational cost may be associated with the combined orchestration changes described in Section~\ref{sec:exp_setup}.

\textbf{Pairwise bootstrap analysis} (10,000 resamples):
(1)~CTU-Chat vs.\ Single Agent: CTU-Chat achieves a 10.0\,pp higher E2E point estimate (76.0\% vs.\ 66.0\%, paired 95\%\,bootstrap CI $[+2.0, +19.0]$\,pp; exact McNemar $p{=}0.0414$), alongside higher Fact Coverage ($\Delta{=}+3.58$\,pp, 95\%\,CI $[-1.2, +8.5]$\,pp) and 41.4\% fewer input tokens alongside 26.1\% fewer total tokens ($\Delta{=}-2{,}044$ total tokens, CI $[-2{,}710, -1{,}378]$; Single: 7{,}826 vs.\ CTU: 5{,}782), at the cost of $+5.49$\,s mean end-to-end latency.
(2)~CTU-Chat vs.\ Routed Generic: specialist policies raise Fact Coverage by $+6.85$\,pp (CI $[+0.7, +13.0]$\,pp, $p{<}0.05$).
(3)~Routed Generic vs.\ Single Agent: comparable token savings ($\Delta{=}-2{,}824$ input tokens) but a $-3.27$\,pp Fact Coverage point estimate (CI $[-9.0, +2.4]$\,pp); the interval includes zero.

On the 20 cross-domain queries, CTU-Chat achieves an 80.0\% E2E point estimate compared with 70.0\% (Single) and 65.0\% (Generic). A sensitivity check across fact-coverage thresholds shows that CTU-Chat has a higher point estimate at $\theta{=}0.50$ (76.0\% vs.\ 66.0\%; +10.0\,pp) and $\theta{=}0.60$ (54.0\% vs.\ 50.0\%; +4.0\,pp), while Single Agent has a slightly higher point estimate at $\theta{=}0.70$ (30.0\% vs.\ 27.0\%), $\theta{=}0.75$ (30.0\% vs.\ 27.0\%), and $\theta{=}1.00$ (25.0\% vs.\ 23.0\%).

\textbf{Latency decomposition:} The $+5{,}493$\,ms mean latency difference between \system{} ($10{,}652$\,ms) and Single Agent ($5{,}159$\,ms) is attributable to two sequential processing stages. First, supervisor dispatch requires an extra round-trip ($2.00$ vs.\ $1.34$ mean LLM calls per query), which accounts for $+3{,}762$\,ms in the intermediate Routed Generic configuration ($8{,}921$\,ms). Second, specialist contract compliance and explicit chain-of-evidence formatting generate $+677$ additional output tokens ($2{,}092$ vs.\ $1{,}415$), contributing the remaining $+1{,}731$\,ms. This generation-phase effect is corroborated by ablation S2-A4 (Section~\ref{sec:s2_results}), where omitting structured calculations and strict contract schemas reduces latency by $4{,}540$\,ms.

The two largest observed degradations occur in \emph{No Specialist Policy} ($\Delta\text{E2E} = -10.0$\,pp, 95\% CI $[-19.0, -1.0]$\,pp; $\Delta\text{Fact} = -6.85$\,pp, CI $[-13.0, -0.7]$\,pp) and \emph{Uniform Text-RAG Baseline} ($\Delta\text{E2E} = -9.0$\,pp, CI $[-15.0, -4.0]$\,pp; $\Delta\text{Src.R} = -12.3$\,pp, CI $[-16.5, -8.3]$\,pp). Removing tool isolation causes no change in point estimate ($\Delta\text{E2E} = 0.0$\,pp, CI $[-6.0, +6.0]$\,pp) while expanding input tokens by $+1{,}270$. Disabling route repair yields $\Delta\text{E2E} = -2.0$\,pp (CI $[-7.0, +3.0]$\,pp), disproportionately harming cross-domain queries ($-15.0$\,pp, dropping from 80.0\% to 65.0\%). Disabling deterministic calculation produces $\Delta\text{E2E} = -4.0$\,pp (CI $[-9.0, 0.0]$\,pp) across the benchmark; on the arithmetic tuition subset ($N{=}9$), exact-match answers drop from 8/9 to 3/9 ($-55.6$\,pp exact match pass) due to unconstrained arithmetic hallucination. Collectively, the ablations distinguish two functional roles: specialist policies, heterogeneous evidence, and deterministic calculation drive accuracy at the current 11-tool scale, while tool isolation (S2-A2) functions as an efficiency mechanism ($+1{,}270$ input tokens, $\Delta\text{E2E} = 0.0$\,pp) whose accuracy contribution is examined under larger registry scales in Scenario~3 (Section~\ref{sec:s3_results}). Query family breakdown in Panel~B confirms that heterogeneous evidence and specialist routing particularly bolster structured financial and cross-domain questions.

As the registry scales from 11 to 51 tools, the Full-Registry Single Agent changes from 86.0\% to 83.3\% E2E while input tokens increase by 124\%. The Global Top-10 changes from 83.3\% to 78.7\% E2E, alongside a Gold Recall change from 100.0\% to 96.0\%. The Routed Specialist records 88.0\% E2E at 51 tools with 9.8 visible tools. At the 51-tool endpoint, Routed Specialist has a +9.3\,pp E2E difference over Top-10 Single Agent (95\% CI $[+2.0, +17.3]$\,pp) and a +4.7\,pp point-estimate difference over Full-Registry Single Agent (95\% CI $[-1.3, +11.3]$\,pp) with 52.4\% fewer input tokens (1{,}770 vs.\ 3{,}722). The degradation interaction (Specialist vs.\ Top-10 high-minus-low difference) is $+7.3$\,pp (95\% CI $[0.0, +15.3]$\,pp).

Analysis of stage-level timing across the 1,960 decisions reveals that Routed Specialist maintains a consistent latency profile across registry expansions ($2{,}091$\,ms at 11 tools vs.\ $2{,}116$\,ms at 51 tools). Here, supervisor routing introduces a fixed overhead of $946.5$--$961.8$\,ms (${\sim}45$\% of total decision time), tool gating requires $1{,}051.6$--$1{,}079.3$\,ms, and tool execution takes $71.0$--$92.8$\,ms. In contrast, while the Full-Registry Single Agent avoids supervisor dispatch ($0$\,ms routing overhead), its gating latency increases from $1{,}098.1$\,ms to $1{,}272.2$\,ms as prompt schema tokens scale from $1{,}663$ to $3{,}722$, demonstrating that the fixed routing overhead of the multi-agent architecture buys sub-linear input token scaling and resistance to semantic interference.
