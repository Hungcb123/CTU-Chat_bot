\subsection{Architectural Findings and Operational Trade-offs}

\textbf{RQ1 (Architecture-Level Effectiveness):}
The architecture-level comparison indicates that supervisor-routed multi-agent decomposition achieves a 10.0\,pp higher E2E point estimate than the Unified Single Agent (76.0\% vs.\ 66.0\%; paired bootstrap CI $[+2.0, +19.0]$\,pp; exact McNemar $p{=}0.0414$), alongside a +3.58\,pp Fact Coverage advantage (95\%\,CI $[-1.2, +8.5]$\,pp) and 41.4\% fewer input tokens (3{,}690 vs.\ 6{,}296), at the expense of higher wall-clock latency (10{,}652 vs.\ 5{,}159\,ms). Routed Generic records lower Fact Coverage than \system{} (54.2\% vs.\ 61.0\%; $\Delta{=}-6.85$\,pp, $p{<}0.05$), indicating that specialist policies contribute substantially to answer fidelity under shared routing.

\textbf{RQ2 (Mechanisms and Tool Isolation Reframe):}
Component ablations reveal two distinct functional roles. \emph{Accuracy drivers:} Heterogeneous evidence access (S2-A3) yields the largest Source Recall drop ($-12.3$\,pp, including $-17.8$\,pp on structured finance); specialist prompt policies (S2-A1) drive Fact Coverage ($-6.85$\,pp); route repair (S2-A5) provides cross-domain resilience ($-15.0$\,pp); and deterministic calculators (S2-A4) prevent arithmetic hallucination ($-55.6$\,pp exact-match on tuition). Conversely, \emph{efficiency and scalability mechanisms:} Tool isolation (S2-A2) does not alter the E2E point estimate at the baseline 11-tool scale ($\Delta\text{E2E} = 0.0$\,pp, CI $[-6.0, +6.0]$\,pp) while expanding input tokens by $+1{,}270$ (+34.4\%). This confirms that at small scales, tool isolation functions primarily as a token-efficiency and cost-containment safeguard rather than an accuracy driver, as the base LLM comfortably handles 11 schemas without severe attention distraction.
The essential value of tool isolation emerges under registry expansion. In Scenario~3, when scaling to 51 tools with semantic distractors, the scoped specialist maintains 88.0\% E2E with 9.8 visible tools, compared with 83.3\% for the Full-Registry Single Agent ($+4.7$\,pp, CI $[-1.3, +11.3]$\,pp) and 78.7\% for Global Top-10 ($+9.3$\,pp, CI $[+2.0, +17.3]$\,pp), while saving 52.4\% input tokens (1{,}770 vs.\ 3{,}722). Tool isolation thus functions as a preventive architectural boundary that limits context expansion and insulates agents against semantic interference as services grow.

\textbf{RQ3 (Tool Ambiguity and Stress Testing):}
Under controlled semantic-neighbor injection across 11--51 tools, the Routed Specialist sustains 88.0\% E2E at 51 tools, whereas Global Top-10 degrades to 78.7\% due to candidate shortlist truncation (Gold Recall dropping to 96.0\%). The Full-Registry Single Agent incurs a 124\% input token penalty to achieve 83.3\% E2E. Specialization effectively decouples per-agent context load from aggregate registry size.

\textbf{Latency Decomposition and Trade-offs:}
The empirical data resolve where latency is expended across architectures. (1)~\emph{Sequential dispatch overhead:} Supervisor routing adds a sequential LLM hop (${\sim}3.8$\,s in Scenario~1; ${\sim}0.95$\,s in Scenario~3) absent in monolithic systems, making single agents faster when tool pools are compact. (2)~\emph{Generation versus dispatch latency:} Latency decomposition demonstrates that the majority of \system{}'s duration is spent in response generation (${\sim}6.8$\,s), where specialist contracts enforce structured evidence citation and reasoning, generating 48\% more output tokens ($2{,}092$ vs.\ $1{,}415$). Ablation S2-A4 confirms that removing structured calculation and contract formatting reduces latency by $4{,}540$\,ms, though compromising calculation exactness. (3)~\emph{Operational guidance:} Monolithic single-agent designs remain preferable for low-latency, single-domain workflows with small tool pools (${\le}10$); supervisor-routed multi-agent designs are justified when institutional counseling demands heterogeneous evidence, calculation fidelity, and scalable tool registries.

\subsection{Relation to Prior Work}

While ReAct~\cite{yao2023react} and Toolformer~\cite{schick2023toolformer} establish tool use within single-agent paradigms, our results indicate that full-registry single agents suffer substantial prompt expansion as tools accumulate. Unlike collaborative multi-agent frameworks (e.g., AutoGen~\cite{wu2023autogen}) where unstructured chatter compounds token consumption and latency, \system{} enforces a bounded, single-owner dispatch model with deterministic route repair. The S2-A3 ablation highlights the fragility of uniform text retrieval on structured relational queries, corroborating the rationale for heterogeneous evidence representations in GraphRAG~\cite{edge2024graphrag}. Furthermore, whereas Adaptive-RAG~\cite{jeong2024adaptiverag} dynamically branches based on linguistic complexity, \system{} routes queries according to institutional data modalities.

\subsection{Threats to Validity}
\label{sec:limitations}
\textbf{Internal:} All primary evaluations utilize Gemini 2.5 Flash Lite with greedy decoding ($\tau{=}0$) to reduce sampling variance; API serving latency and backend scheduling variations remain potential operational confounds. \textbf{External:} The benchmark is grounded in statutes and curricula from Can Tho University; validation across multi-campus institutions with bilingual or trimester policies remains future work. Semantic-neighbor tools in Scenario~3 are controlled synthetic constructs modeling intra-domain ambiguity. \textbf{Construct:} Metric scoring incorporates automated evaluation via Ragas alongside deterministic exact-match checks; human verification was conducted on a subset to validate metric concordance. \textbf{Statistical:} Evaluations are based on 100 held-out cases with paired bootstrap resampling (10,000 iterations); the arithmetic sub-cohort ($N{=}9$) has a small sample size, though the difference in exact match (8/9 vs.\ 3/9) is substantial. \textbf{Operational:} Latency measurements reflect cloud-hosted API execution and public network connectivity.
